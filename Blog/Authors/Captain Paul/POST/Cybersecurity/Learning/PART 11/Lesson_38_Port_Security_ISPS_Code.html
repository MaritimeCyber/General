Port Security and the ISPS Code

Captain Paul
Maritime Cybersecurity · IACS UR E26/E27
September 2026
🎯 Lesson Objective

After this lesson you can explain the structure and requirements of the International Ship and Port Facility Security (ISPS) Code, describe the roles of the Company Security Officer (CSO), Ship Security Officer (SSO), and Port Facility Security Officer (PFSO), explain how cybersecurity integrates into Ship Security Assessment and Ship Security Plan requirements, understand the three ISPS Security Levels and their implications for vessel operations, and describe port-side cyber threats and how they interact with vessel cybersecurity at the port interface.

The International Ship and Port Facility Security (ISPS) Code — mandatory under SOLAS Chapter XI-2 from July 2004 — was the maritime industry's first mandatory security framework. Developed in the wake of the September 11, 2001 attacks, ISPS focuses primarily on physical security: protecting vessels and port facilities from terrorism, unlawful access, and acts that could threaten maritime safety. Its framework — security assessments, security plans, security officers, and security levels — provides the operational infrastructure that maritime cybersecurity programmes can and should leverage.

The ISPS Code does not mention cybersecurity by name. But its core concepts — identifying threats and vulnerabilities, developing plans to address them, maintaining continuous security awareness, and operating at graduated security levels — are directly applicable to cyber threats. IMO and IACS both explicitly encourage integrating cyber security into existing ISPS frameworks rather than creating parallel structures. For vessels already ISPS-compliant, the cyber security programme is an extension of an established framework, not a replacement.

The port interface is also where vessel cybersecurity and port-side cybersecurity intersect. Ports are complex IT/OT environments with terminal management systems, cargo handling automation, gate access control, and vessel traffic services — all of which interact with vessels through communications, data exchanges, and physical connections. Understanding the port-side cyber threat landscape, and how the ISPS framework addresses the vessel-port security interface, is an increasingly important part of maritime cybersecurity.

1. ISPS Code Structure and Key Requirements

1. ISPS Code Structure and Key Requirements
1
Ship Security Assessment (SSA)

The Ship Security Assessment is the ISPS Code equivalent of a risk assessment. It must identify: the existing security measures, procedures, and operations on the vessel; key shipboard operations that it is important to protect; possible threats to those operations and the likelihood of their occurrence; and weaknesses including human factors, in the infrastructure, policies and procedures of the vessel. For E26 integration, the SSA is the natural framework for the initial cyber risk identification exercise: cyber threats to vessel operations are exactly the type of threat the SSA is designed to identify, and an E26-compliant Cyber Risk Assessment can be structured as a cyber-specific annex to the SSA.

2
Ship Security Plan (SSP)

The Ship Security Plan is the operational document implementing the security measures identified in the SSA. The SSP must address: measures to prevent weapons and dangerous substances from being taken aboard without authorisation; measures for the prevention of unauthorised access; procedures for responding to security threats or breaches; procedures for evacuation in case of security threats or breaches; duties of shipboard personnel assigned security responsibilities; procedures for auditing the security activities; procedures for reporting security incidents; identification of the SSO; and identification of the Company Security Officer. Cyber incident response procedures — required by IACS UR E26 — are exactly the type of 'procedures for responding to security threats or breaches' that the SSP must contain.

3
Security Officers and Responsibilities

The ISPS Code creates three security officer roles: Company Security Officer (CSO) — designated by the shipping company, responsible for ensuring the SSA and SSP are developed and maintained, liaising with port facility security officers, and ensuring security personnel receive appropriate training. Ship Security Officer (SSO) — vessel-based officer responsible for implementing and maintaining the SSP, reporting security incidents to the CSO, and conducting regular security inspections. Port Facility Security Officer (PFSO) — port-side counterpart to the SSO, responsible for the Port Facility Security Assessment and Port Facility Security Plan. Cyber security responsibilities under E26 should be explicitly assigned to these roles: the CSO is typically responsible for the fleet-level E26 compliance programme, and the SSO for vessel-level implementation.

2. ISPS Security Levels and Cyber Implications

2. ISPS Security Levels and Cyber Implications
1
Three Security Levels

ISPS defines three Security Levels: Level 1 (Normal) — the level at which the ship normally operates; minimum appropriate protective security measures are maintained at all times. Level 2 (Heightened) — the level applying for as long as there is a heightened risk of a security incident; additional protective measures are implemented for a period of time as a result of a heightened risk of a security incident. Level 3 (Exceptional) — the level applying for the period of time when there is a probable or imminent risk of a security incident; further specific protective measures are implemented for a limited period of time. Security levels are set by the competent authority of the port state and communicated to vessels before port entry.

2
Cyber Threat Security Level Integration

Cyber threats can justify Security Level escalation under the ISPS framework. If a specific cyber threat to a vessel or vessel class is received (e.g. a credible threat from a threat intelligence source indicating a specific vessel type is being targeted), the company may escalate to Security Level 2 and implement additional protective measures — including enhanced network monitoring, additional remote access restrictions, or temporary shutdown of non-essential external connections. This ISPS mechanism provides the operational framework for implementing elevated cyber defences in response to elevated threat intelligence, using the crew and company structures already established under ISPS.

3
Port Entry Security Procedures

Before entering port, vessels must declare their current Security Level and confirm they have been continuously operated at Security Level 1 or above for the 10 previous port calls. A vessel that has experienced a security breach (including a cyber incident) during the preceding port calls may be required to confirm this and explain the incident. Ports may conduct a Declaration of Security (DoS) with the vessel before alongside operations — a formal agreement between the SSO and PFSO specifying security measures in effect for the duration of port call. Cyber incidents should be considered reportable security breaches in the context of port entry declarations, and the SSP should specify what cyber incidents require declaration to port authorities.

3. Port-Side Cyber Threats and the Vessel Interface

3. Port-Side Cyber Threats and the Vessel Interface
1
Port IT/OT Environment

Modern ports are complex IT/OT environments: Terminal Operating Systems (TOS) manage container movements, crane automation, and yard operations; Port Community Systems (PCS) connect port authorities, terminals, shipping lines, customs, and freight forwarders; Vessel Traffic Service (VTS) systems track vessel positions in port approaches; Gate access control systems manage truck movements. Each of these systems has cyber vulnerabilities, and each connects to vessels through data exchanges — cargo manifests, berthing instructions, dangerous goods declarations, customs clearance data. A compromised Port Community System could send false cargo data to a vessel, or a compromised VTS system could provide inaccurate navigation instructions.

2
Vessel-Port Data Exchange Attacks

The vessel-port data exchange is a specific attack surface: cargo manifest data exchanged between the vessel's cargo management system and the port's terminal operating system; dangerous goods declarations sent from the vessel to port authorities; electronic bill of lading and documentation exchanged via Port Community Systems; pre-arrival notifications submitted to customs and border authorities. These exchanges are typically conducted via email, web portals, or EDI (Electronic Data Interchange) — formats that are susceptible to business email compromise, data manipulation, and man-in-the-middle attacks. An attacker who compromises the manifest exchange can conceal smuggled cargo, manipulate dangerous goods declarations, or facilitate customs fraud.

3
Shore Power and Physical Port Connections

At berth, vessels often connect to shore power and may connect physical IT connections (internet, shore-to-ship cable connections for high-bandwidth data transfer). Shore power connections are not a direct cyber attack vector, but the physical presence of unknown personnel (port workers, surveyors, inspectors) during port calls is an ISPS physical security concern that also has cyber implications — an unauthorised USB device left in a bridge workstation by a port inspector (social engineering or state-sponsored supply chain attack) is a documented attack scenario. The SSP procedures for controlling access during port calls also protect against this cyber-physical attack vector.

✍️ Author Insight — From the Field
Captain Paul · Maritime Cybersecurity Consultant · IACS UR E26/E27

During E26 CRSI assessments that include port call security reviews, the most consistent finding is that the Ship Security Plan's visitor access control procedures are not enforced during port calls in a way that addresses cyber risk. The SSP specifies that all visitors must be logged and escorted — but in practice, port inspectors, class surveyors, and equipment service technicians frequently have unsupervised access to the bridge, engine control room, and server spaces during port calls. Any of these individuals could plug a USB device into a vessel workstation during the minutes they spend unescorted in these spaces. The fix is not to make port calls hostile to legitimate visitors — it is to implement the SSP's own procedures: log every visitor, assign an escort from the crew, and include in the escort briefing that vessel IT equipment should not be touched without the chief officer's explicit permission. This procedural control, already required by the SSP, is the most practical cyber-physical security control available at port.

Practical first step: Review your SSP's visitor access control procedure. Does it specify that vessel IT equipment (workstations, servers, network equipment) should not be accessed by visitors without explicit officer permission? Does the vessel log include a field for the purpose and areas accessed by each visitor? If not, update the SSP visitor log template to add IT equipment access as a specific item to be recorded. Brief the SSO on this update at the next vessel security training session.

✅ Key Takeaways — Lesson 38
  • The ISPS Code provides the operational security framework (SSA, SSP, security officers, security levels) into which maritime cybersecurity can be integrated — the E26 Cyber Risk Assessment and incident response procedures are natural additions to the existing ISPS structure.
  • The Company Security Officer (CSO) and Ship Security Officer (SSO) are the appropriate roles for E26 cyber security responsibilities — the CSO for fleet-level compliance, the SSO for vessel-level implementation.
  • ISPS Security Levels provide the operational mechanism for implementing elevated cyber defences in response to elevated threat intelligence — a cyber threat can justify Level 2 escalation with additional network monitoring and access restrictions.
  • Port-side cyber threats — compromised Terminal Operating Systems, Port Community System data manipulation, vessel-port data exchange attacks — interact with vessel cybersecurity at every port call through cargo manifest, dangerous goods, and documentation exchanges.
  • Physical access during port calls is a cyber-physical attack vector: unsupervised visitor access to bridge and engine room spaces enables USB-based malware delivery — SSP visitor access control procedures directly address this vector.
  • Cyber incidents should be treated as reportable security breaches under ISPS — the SSP should specify what cyber incidents require declaration to port authorities on port entry.
