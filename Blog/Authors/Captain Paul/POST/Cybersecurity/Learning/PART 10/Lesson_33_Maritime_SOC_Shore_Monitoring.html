Maritime SOC and Shore-based Cyber Monitoring

Captain Paul
Maritime Cybersecurity · IACS UR E26/E27
September 2026
🎯 Lesson Objective

After this lesson you can describe how a shore-based SOC monitors a fleet of vessels, explain the connectivity and operational adaptations required for maritime fleet monitoring, understand the commercial maritime SOC service models (in-house, MSSP, hybrid), describe the operational procedures for responding to a vessel cyber incident from shore, and explain what IACS UR E26 requires in terms of monitoring and incident response capability.

A vessel at sea is not monitored by anyone for cybersecurity in the vast majority of the global fleet. The bridge has no security displays. The shore office IT team receives no vessel security alerts. The SOC — if the shipping company has one — monitors shore-based systems only. The vessel is operationally isolated from the security monitoring infrastructure that might detect an ongoing attack. This is the current reality for most commercial shipping.

The maritime SOC — a shore-based security operations capability specifically designed to monitor vessel fleets — is the operational model that closes this gap. It combines vessel-side telemetry collection (OT network sensors, log forwarders, vessel EDR agents) with shore-side aggregation (SIEM, OT platform) and analyst coverage (in-house or MSSP) to provide continuous visibility into vessel security status. When an anomaly is detected, the maritime SOC initiates communication with the vessel and coordinates the response.

The maritime SOC model is not simply a copy of an enterprise IT SOC applied to vessels. It requires adaptation for the unique operational constraints of maritime: bandwidth-limited telemetry, time zone coverage for vessels operating globally, maritime domain knowledge for analysts to correctly interpret vessel-specific events, and operational procedures that account for the vessel master's authority and the crew's role as first responders.

1. Maritime SOC Architecture

1. Maritime SOC Architecture
1
Vessel-Side Collection

The vessel-side collection layer aggregates telemetry from all available vessel sources: OT network sensor (passive Claroty/Nozomi sensor on OT SPAN port), vessel firewall/router logs, VSAT management access logs, vessel EDR agents on bridge and engine room workstations, ECDIS event logs where accessible, and AIS data stream. A vessel-based log aggregator (lightweight Linux server or hardened appliance) collects all sources, buffers during connectivity outages, prioritises high-severity events for immediate transmission, and compresses/encrypts the data stream for VSAT transmission.

2
Shore-Side Aggregation

The shore-side aggregation layer receives vessel telemetry from all vessels in the fleet, normalises it to a common schema, indexes it in the SIEM, and makes it available for the OT platform and SOC analysts. The aggregation layer must handle: fleet-scale log volume (50 vessels × average 100MB/day = 5GB/day), telemetry gaps during VSAT outages (data arriving in bursts after reconnection), multi-vessel correlation (detecting the same attack pattern appearing across multiple vessels simultaneously), and vessel context enrichment (tagging every event with the vessel name, IMO number, fleet segment, and current operational status).

3
Analyst Coverage Model

The maritime SOC can be structured as: (1) In-house (shipping company employs SOC analysts with maritime domain knowledge — typically only viable for large operators with 50+ vessels and dedicated security budgets). (2) MSSP (a commercial maritime security service provider provides 24/7 monitoring, alert triage, and incident response services on a contracted basis — the most common model for mid-size operators). (3) Hybrid (in-house security engineer manages detection content, OT platform, and threat intelligence; MSSP provides 24/7 Tier 1 alert monitoring). The hybrid model provides the best balance of in-house control and coverage scale for most mid-size shipping companies.

4
Fleet Dashboard

The maritime SOC fleet dashboard provides the operational view: a map or list of all monitored vessels with real-time security status indicators, current alert counts by vessel and severity, vessel connectivity status (which vessels have active VSAT links, which are in a telemetry gap), recent incidents by vessel, and compliance indicators (which vessels are current on patch status, which have active remote access sessions). This dashboard is the SOC analyst's starting point for each shift — a situational awareness view of the entire fleet's security status in a single screen.

2. Operational Procedures for Vessel Incidents

2. Operational Procedures for Vessel Incidents
1
Shore-to-Vessel Communication

When the maritime SOC detects an anomaly on a vessel, the first response step is shore-to-vessel communication: contacting the vessel master or chief officer via the most reliable available channel (satellite phone, email, GMDSS message) to report the detection and request confirmation. The communication must be clear about: what was detected, which system is potentially affected, what the crew should observe or check, and what immediate actions the crew should take (if any). This communication is documented as the first step in the incident record.

2
Crew First Responder Procedures

Vessel crew are the maritime SOC's eyes and hands on the vessel. Pre-defined crew cyber incident response procedures (included in the Ship Security Plan under ISPS Code requirements, and increasingly required under IACS UR E26 Ship Security Plans) define what the crew should do when directed by the shore SOC or when they observe a cyber anomaly themselves: which systems to disconnect from the network, how to preserve evidence (log exports, photographs of unusual displays), how to switch to manual/backup navigation procedures if safety-critical systems are affected, and how to communicate the incident to shore.

3
Remote SOC Response Actions

Where vessel systems support remote management (VSAT router, vessel firewall, remote access VPN), the maritime SOC can take direct response actions without requiring crew involvement: blocking suspicious IP addresses at the vessel firewall, terminating active remote access sessions, changing credentials on the VSAT management interface. Remote EDR capabilities (if deployed on vessel workstations) enable network isolation of compromised endpoints. Remote response capabilities must be documented, tested, and limited to pre-approved actions — an SOC analyst accidentally disabling the wrong system remotely on a vessel at sea could create a safety incident.

4
Escalation to Incident Response

When a vessel cyber incident is confirmed, the maritime SOC escalates to the formal incident response process: notifying the shipping company's incident response team, engaging the maritime cybersecurity service provider (if contracted), notifying the vessel master and shipowner, and determining whether regulatory notification is required (flag state, port state control, GMDSS authorities). Large vessel cyber incidents may also require notification of the vessel's P&I club (Protection and Indemnity insurance) and hull and machinery underwriters — most maritime cyber insurance policies require prompt notification of incidents to preserve coverage.

3. Commercial Maritime SOC Services and E26 Compliance

3. Commercial Maritime SOC Services and E26 Compliance
1
Maritime MSSP Landscape

The commercial maritime SOC service market has grown significantly since 2018, driven by IACS UR E26/E27 requirements and high-profile incidents. Key providers include: Naval Dome, CyberOwl, Redscan Maritime, Sapura Secured Technologies, and divisions of major maritime service companies (Bureau Veritas Cyber Security, DNV Cyber). These services typically provide: vessel security monitoring (sensor deployment and telemetry collection), shore-based SOC coverage (24/7 alert monitoring and response), incident response support, and compliance reporting for E26/E27 and ISM Code requirements. Pricing is typically per-vessel per-month, ranging from USD 500-2,500 depending on service level and sensor coverage.

2
IACS UR E26 Monitoring Requirements

IACS UR E26 requires that vessels have capability to detect cyber incidents and that appropriate response procedures exist. Specifically, E26 requires: (1) Security monitoring capability for computer-based systems used for ship functions. (2) Documented incident response procedures. (3) Mechanisms for reporting cyber incidents to the shipowner. The E26 requirement does not specify the form of monitoring — on-vessel sensors, shore-based SIEM, or commercial MSSP services are all acceptable approaches, provided they meet the capability requirement of detecting incidents affecting ship functions.

3
E26 Compliance Reporting

Maritime SOC services typically include E26 compliance reporting: monthly security summary reports for the ISM audit record, evidence of monitoring capability for class society survey, incident records with documented response actions, and vulnerability management tracking (patch status by vessel, outstanding CVEs, scheduled maintenance windows). These reports form part of the vessel's cyber risk management documentation required by IACS UR E26 and increasingly requested by port state control inspectors.

✍️ Author Insight — From the Field
Captain Paul · Maritime Cybersecurity Consultant · IACS UR E26/E27

During E26 CRSI assessments, the maritime SOC conversation is where the gap between compliance requirement and operational reality is most visible. IACS UR E26 requires monitoring capability; the assessment finds no vessel telemetry reaching the shore-based IT team, no SOC alert channel for vessel events, and no documented procedure for what a crew member should do if they suspect a cyber incident. The commercial maritime SOC service market exists precisely because most shipping companies cannot build this capability in-house cost-effectively. For a fleet of 10-30 vessels, a commercial maritime SOC service at USD 1,000-2,000 per vessel per month provides monitoring coverage, compliance documentation, and incident response support that would cost 5-10x more to replicate with in-house staffing. The E26 implementation path for mid-size operators almost always includes a commercial maritime SOC service as the monitoring solution.

Practical first step: Define your vessel cyber incident communication chain before you need it. Who calls the vessel when the SOC detects an anomaly? What phone number? Who on the vessel is the cyber incident first responder contact? Is there a procedure for what they do? Write this down as a one-page vessel cyber incident response quick reference card — the vessel master's name, the SAT phone number, the three actions they take when called about a cyber incident. Laminate it. Put it on the bridge. This preparation costs nothing and is the prerequisite for every other incident response capability.

✅ Key Takeaways — Lesson 33
  • The maritime SOC monitors vessel fleets from shore, aggregating vessel-side telemetry (OT sensors, firewall logs, EDR agents) through a SIEM into a fleet dashboard visible to security analysts.
  • Maritime SOC commercial service models — in-house, MSSP, hybrid — provide shipping companies with 24/7 monitoring capability without the headcount cost of full in-house SOC staffing.
  • Shore-to-vessel communication at incident detection is the critical maritime SOC procedure: contacting the vessel master, providing clear detection information, and directing crew first responder actions.
  • Crew first responder procedures — pre-defined, tested, and in the Ship Security Plan — define what vessel crew do before shore-side response team involvement: network isolation, evidence preservation, manual fallback.
  • IACS UR E26 requires security monitoring capability for ship functions and documented incident response procedures — commercial maritime SOC services provide both capabilities at a per-vessel cost that is viable for mid-size operators.
  • E26 compliance reporting from commercial SOC services (monthly security summaries, vulnerability tracking, incident records) satisfies class society survey requirements and port state control documentation requests.
