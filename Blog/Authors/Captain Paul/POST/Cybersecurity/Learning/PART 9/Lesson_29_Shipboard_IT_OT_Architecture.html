Shipboard IT and OT Architecture

Captain Paul
Maritime Cybersecurity · IACS UR E26/E27
September 2026
🎯 Lesson Objective

After this lesson you can describe the typical IT and OT network architecture of a modern commercial vessel, identify the key OT systems by function (navigation, propulsion, cargo, safety), explain the convergence points between IT and OT networks and why they are security risks, describe the IEC 62443 zone and conduit model as applied to vessel network segmentation, and explain what IACS UR E26 requires in terms of network architecture.

A modern commercial vessel is a floating data centre and industrial control system simultaneously. On the IT side: a corporate network for vessel administration and communications, a crew internet network for personal use, VSAT terminals and satellite modems, Windows workstations for bridge officers and engineers, email servers, and connections to fleet management platforms ashore. On the OT side: navigation systems (ECDIS, AIS, GPS, radar), propulsion and engine management systems, cargo handling systems (for tankers, bulk carriers, container ships), ballast water management, fire detection and suppression, and safety systems.

These two worlds — IT and OT — have historically been separate. The OT network was air-gapped or physically isolated from the IT network and from external connections. Maintenance was performed by technicians physically present on the vessel. Updates were applied manually. This isolation was never intentional security design; it was simply how these systems were built and operated before internet connectivity became standard.

Today, the air gap is gone for most modern vessels. Fleet management platforms require real-time data from OT systems. Remote maintenance contracts require vendor access to engine monitoring systems. Chart update services connect to ECDIS directly. The isolation that provided de facto security has been replaced by connectivity that provides operational efficiency — and attack surface.

1. Vessel IT Network Architecture

1. Vessel IT Network Architecture
1
Administrative Network

The vessel's administrative network supports business functions: officer workstations for voyage documentation, cargo planning, and administrative tasks; a file server for vessel documents; email and messaging; and connections to the shipowner's shore-based IT systems via the VSAT link. This network typically runs Windows workstations and standard enterprise network equipment, and is the most similar to a shore-based enterprise IT environment. It is also the most likely entry point for commodity cyber attacks (phishing, ransomware) targeting the vessel.

2
Crew Network

Most modern vessels provide crew internet access via a segregated network — separate from the administrative network — allowing crew members to access personal email, video calls, and streaming services via their own devices. Crew networks introduce significant risk: personal devices bring malware, phishing links are clicked outside of any corporate security control, and the crew network's connection to the VSAT shares bandwidth with the operational network. Crew network segregation quality varies enormously — from properly isolated VLANs to a shared switch with no segmentation.

3
VSAT and Communications

The VSAT system is the vessel's gateway to the internet and to shore-based systems. It includes a modem, a router, and typically a management interface accessible remotely for configuration and monitoring by the satellite provider. The VSAT management interface is one of the highest-risk components on a vessel: it is externally accessible, often runs default or weak credentials, and provides privileged access to the vessel's entire internet gateway. VSAT management interfaces have been the initial access vector in multiple documented maritime cyber incidents.

2. Vessel OT Network Architecture

2. Vessel OT Network Architecture
1
Navigation Systems

Navigation OT systems include: ECDIS (Electronic Chart Display and Information System — the primary navigation tool, displaying electronic charts with GPS position overlay), AIS (Automatic Identification System — broadcasting and receiving vessel identity and position), radar systems, GPS receivers, and the Integrated Navigation System (INS) that integrates these into a unified bridge display. These systems communicate using maritime-specific protocols: NMEA 0183 and NMEA 2000 for sensor data, IEC 61162 for inter-system communication. They run proprietary software on dedicated hardware, often with OS versions 5-10 years behind current.

2
Propulsion and Engine Management

Engine and propulsion OT systems include: the Engine Control Room (ECR) management system, auxiliary machinery monitoring, fuel management, propulsion control (variable pitch propellers, thruster control on DP vessels), and increasingly, condition monitoring and predictive maintenance systems that stream performance data to shore. These systems are typically Modbus or proprietary protocol-based, run on PLCs (Programmable Logic Controllers), and connect to the ship's network for data sharing with performance monitoring platforms.

3
Cargo and Safety Systems

Cargo OT varies by vessel type: tankers have cargo pump control and gas detection; container ships have reefer monitoring and container tracking; bulk carriers have hold monitoring. All vessel types carry safety OT: fire detection and alarm systems, flooding/bilge alarm systems, CO2 suppression systems, emergency shutdown systems. Safety systems have the highest integrity requirements — a false-triggered CO2 suppression in an engine room can incapacitate machinery and crew.

3. Network Segmentation and the Zone/Conduit Model

3. Network Segmentation and the Zone/Conduit Model
1
The Convergence Problem

The IT/OT convergence problem arises where the two networks must share data. Fleet management platforms need real-time engine data. Chart update services need to reach the ECDIS. Performance monitoring needs propulsion data. Each data-sharing connection is a potential attack path from IT to OT. In practice, these connections are often implemented as direct network connections between IT and OT segments — without firewalls, without protocol filtering, and without monitoring — creating a path from the crew internet network to the navigation system.

2
IEC 62443 Zones and Conduits

The IEC 62443 standard provides the primary framework for OT network segmentation. It defines Zones (groups of systems with similar security requirements and trust levels) and Conduits (controlled connections between zones that enforce security policy). Applied to a vessel: Zone 1 (external connectivity — VSAT, internet), Zone 2 (vessel IT — administrative and crew networks), Zone 3 (vessel OT — navigation systems), Zone 4 (safety-critical OT — safety systems with highest integrity requirements). Conduits between zones are implemented as firewalls, data diodes (for one-way data flow from OT to IT), or DMZ architectures.

3
IACS UR E26 Network Requirements

IACS UR E26 requires that vessels implement network segmentation to separate OT systems from IT systems and from external networks, with access control at segment boundaries. The specific requirement is that 'computer-based systems used for ship functions' are in a protected network segment, separated from business IT and crew networks by firewalls with documented rule sets. E26 also requires that remote access to OT systems is controlled, logged, and provided only through approved access methods — not through open internet connections to the OT network directly.

✍️ Author Insight — From the Field
Captain Paul · Maritime Cybersecurity Consultant · IACS UR E26/E27

During E26 CRSI assessments, the network architecture finding is almost universal: the vessel's IT and OT networks are not properly segmented. The typical finding is a flat network where the crew Wi-Fi VLAN, the administrative workstation VLAN, the ECDIS, and the engine monitoring system are all on the same physical network switch, with no firewall between them. An attacker who compromises the crew Wi-Fi network — through a phishing link clicked on a crew member's personal device — has network-level access to the bridge navigation systems and engine OT network without any additional exploitation step. The path from 'phishing click on crew device' to 'ECDIS access' is one hop on a properly analysed switch, not a sophisticated multi-stage attack. Fixing this — implementing proper VLAN segmentation, deploying a vessel firewall with documented rules, and restricting direct IT-to-OT connectivity — is typically the highest-priority technical recommendation in every vessel assessment.

Practical first step: Draw your vessel's network diagram before your next port inspection. Include: every VLAN or network segment, every connection between segments (and whether there is a firewall on that connection), every device on each segment, and every external connection (VSAT, remote maintenance VPN, chart update service). If you cannot draw this diagram from memory or documentation — if no one on the vessel knows what is connected to what — you have a network architecture problem that must be resolved before any other security control can be effectively implemented.

✅ Key Takeaways — Lesson 29
  • Modern vessels have both IT (administrative, crew, communications) and OT (navigation, propulsion, cargo, safety) networks — each with different security requirements, protocols, and risk profiles.
  • The maritime IT/OT convergence problem arises where operational data sharing requirements (fleet management, remote maintenance, chart updates) create network connections between IT and OT segments that become attack paths.
  • Maritime OT systems use proprietary protocols (NMEA 0183/2000, Modbus, IEC 61162) on dedicated hardware running legacy OS versions — incompatible with standard enterprise security tools and requiring OT-specific security approaches.
  • The IEC 62443 zone and conduit model provides the segmentation framework: zones group systems by trust level, conduits provide controlled inter-zone connectivity enforced by firewalls or data diodes.
  • IACS UR E26 requires network segmentation separating OT from IT and external networks, with firewall-enforced access control and documented rule sets at segment boundaries.
  • The most common vessel network finding: flat networks with crew Wi-Fi, administrative workstations, ECDIS, and engine OT on the same switch — one compromise away from safety-critical system access.
