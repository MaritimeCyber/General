PART 12 · Lesson 1 E26/E27 Integration Type Approval · Ship Compliance

From E27 Type Approval to E26 Ship Integration

Captain Paul
Maritime Cybersecurity · IACS UR E26/E27
September 2026
🎯 Lesson Objective

After this lesson you can trace the complete compliance journey from E27 equipment type approval to E26 ship-level integration, describe the specific handoff points where manufacturer responsibility transitions to shipowner responsibility, explain how a newbuild vessel achieves E26/E27 compliance through the shipyard and class society survey process, describe the retrofit compliance path for existing vessels, and articulate what a fully integrated maritime cyber resilience programme looks like in operational terms.

This lesson brings together the regulatory threads of PART 11 into a single integrated compliance journey. We trace the path from the moment a manufacturer begins developing E27-compliant navigation equipment through to the moment a vessel operating that equipment is verified as E26-compliant by a class society surveyor. Understanding this end-to-end journey — who does what, in what sequence, and how the different elements connect — is the practical knowledge that maritime cybersecurity professionals need to build and verify maritime cyber resilience programmes.

The compliance journey differs for newbuild vessels (where E27/E26 is designed in from the start) and existing vessels (where E27 compliance must be assessed for already-installed equipment and E26 compliance must be retrofitted into an operating vessel). Both paths arrive at the same destination — an E26-compliant vessel — but through different processes with different challenges.

The lesson closes with a description of what an integrated, operationally mature maritime cyber resilience programme looks like: not just compliance paperwork, but a functioning programme with active monitoring, regular testing, crew training, and a continuous improvement cycle that keeps the programme effective as threats evolve and systems change.

1. Newbuild Compliance Journey

1. Newbuild Compliance Journey
1
Phase 1 — Specification and Equipment Selection

During the vessel specification phase, the shipowner (supported by their technical manager and potentially a maritime cybersecurity consultant) defines the cybersecurity requirements for the newbuild: the target Security Level (SL-T) for each system category, the network architecture including zone and conduit design, and the requirement for E27 Type Approved equipment in all covered categories. Equipment tenders include E27 Type Approval as a mandatory requirement. This phase establishes the cybersecurity architecture that the entire compliance programme will be built around — changes at later phases are expensive. Class society pre-approval of the cybersecurity architecture at specification stage avoids design iterations during detailed design.

2
Phase 2 — Shipyard Design and Build

During the design and build phase, the shipyard integrates E27-compliant equipment according to the E26-required network architecture: installing OT systems in their defined security zone, implementing firewall-enforced conduits between zones, configuring authentication on all covered systems according to E27 Type Approval conditions, enabling logging on all covered systems, and installing the OT monitoring sensor (if included in the newbuild specification). The shipyard prepares the network architecture documentation that will form part of the E26 compliance package. At delivery, the shipyard submits the E26 compliance documentation package to the class society for initial classification survey.

3
Phase 3 — Class Society Initial Survey

The class society initial survey for E26 compliance verifies: the Cyber Risk Assessment (draft CRA prepared by the shipowner or their consultant, reviewed against the vessel's actual configuration at survey), network architecture (physical verification that the installed network matches the documented architecture, including firewall rule verification), access control implementation (credential management verification on a sample of covered systems), logging configuration (verification that event logging is active and that logs are being collected), and incident response procedures (review of the SSP or SMS cyber annex against E26 Respond requirements). Successful survey results in E26 notation in the class certificate.

2. Existing Vessel Retrofit Path

2. Existing Vessel Retrofit Path
1
Gap Assessment — Starting Point

The retrofit compliance journey begins with a gap assessment: a systematic evaluation of the existing vessel against E26 functional requirements. The gap assessment identifies: the current network architecture and its deviations from E26 zone/conduit requirements (most common finding: flat IT/OT network with no firewall between segments), the access control status of covered systems (most common finding: default or shared credentials unchanged), the logging configuration of covered systems (most common finding: logging not enabled or logs not collected), and the existing documentation (most common finding: no vessel-specific CRA exists). The gap assessment output is a prioritised remediation plan — the inputs for the E26 retrofit programme.

2
Remediation Sequencing

E26 retrofit remediation is typically sequenced by risk impact: (1) Network segmentation — installing vessel firewall between IT and OT segments, configuring VLAN segregation for crew, admin, and OT networks (highest impact, can be done during port call with planned maintenance window); (2) Access control — changing default credentials on covered systems, implementing per-user authentication where supported, restricting remote access to whitelist (medium complexity, may require OEM support for legacy systems); (3) Logging — enabling event logging on covered systems, deploying log collection agent or configuring syslog forwarding to shore-based SIEM (low disruption, can often be done remotely with OEM support); (4) Documentation — preparing the CRA, updating network architecture diagrams, developing incident response procedures (office-based, parallel to technical remediation).

3
Class Society Survey for Existing Vessels

Most IACS class societies implement E26 for existing vessels at the next scheduled Special Survey (every 5 years) or a dedicated E26 verification survey. The survey process mirrors the newbuild survey but adds a gap-closing verification step: the surveyor reviews the gap assessment and remediation history, verifies that identified gaps have been closed, and assesses residual risks against the CRA's compensating controls. Vessels that cannot achieve full E26 compliance by the survey date may receive conditions of class — time-limited requirements to close specific gaps — rather than outright deficiency. Class societies recognise that E26 retrofit for existing vessels is a multi-year programme for many operators.

3. Operational Cyber Resilience Programme

3. Operational Cyber Resilience Programme
1
Programme Elements

An operationally mature maritime cyber resilience programme has eight components: (1) Governance — CSO/SSO cyber responsibilities, board-level cyber risk reporting, annual programme review. (2) Asset Management — continuously updated vessel asset inventory and network architecture documentation. (3) Risk Management — Cyber Risk Assessment maintained and updated at significant changes and periodic surveys. (4) Technical Controls — network segmentation, access control, patch management implemented and verified. (5) Detection and Monitoring — maritime SOC or commercial MSSP providing 24/7 vessel monitoring with fleet dashboard. (6) Incident Response — tested cyber incident response procedures for vessel crew and shore response team. (7) Recovery — backup and restoration procedures tested at least annually per vessel. (8) Training — annual crew cyber awareness training integrated with STCW safety training, annual tabletop exercise for shore response team.

2
Continuous Improvement Cycle

The programme must have a continuous improvement cycle: threat intelligence (receiving and reviewing maritime-specific threat intelligence, updating the CRA when new threat information is relevant), patch management (receiving E27 vulnerability notifications from manufacturers, scheduling and applying patches within the defined patching window), incident learning (reviewing every detected security event — not just confirmed incidents — for detection rule improvement and control gap identification), and programme metrics (tracking KPIs: mean time to patch for critical vulnerabilities, proportion of covered systems with active logging, crew training completion rates, number of hunts performed). The continuous improvement cycle transforms E26 compliance from a point-in-time certification into an ongoing operational security programme.

3
Integration with SMS and ISM Audit

The maritime cyber resilience programme must be integrated into the vessel's Safety Management System for ISM Code compliance: the CRA as an SMS document reviewed in the annual SMS internal audit, cyber incident response procedures as SMS emergency procedures exercised in drills, cyber security training records as part of the crew training records maintained under the SMS, and the programme annual review as part of the management review process required by the ISM Code. This SMS integration ensures that the cyber resilience programme is visible to flag state ISM auditors and port state PSC inspectors, not just to the class society surveyor.

✍️ Author Insight — From the Field
Captain Paul · Maritime Cybersecurity Consultant · IACS UR E26/E27

During E26 CRSI assessments covering the entire compliance journey, the integration step that most consistently fails is the handoff from newbuild shipyard to shipowner operations. The shipyard delivers the vessel with E26 compliance documentation prepared for the initial class survey — but the documents reflect the vessel as built, not the vessel as operated. Six months into operations, equipment has been replaced for maintenance reasons without E27 documentation update, remote access credentials have been shared with vendors without the access log being maintained, and the network architecture has been modified for a new performance monitoring system without firewall rule update. The E26 compliance that was achieved at delivery has eroded through normal operational change management processes that didn't include cybersecurity update steps. The fix is change management integration: the same process that authorises modification to a vessel's engine plant should include a cybersecurity impact assessment step that updates the CRA and network architecture when relevant. Without this integration, compliance is a delivery-day achievement rather than an operational reality.

Practical first step: Build a one-page 'cyber change checklist' that vessel managers complete when any change is made to covered systems: new equipment installed (triggers E27 assessment and CRA update), network connection added (triggers firewall rule review and network architecture update), new vendor remote access granted (triggers access log entry and review), software updated (triggers patch record and CRA version update). Attach this checklist to the vessel's planned maintenance system as a mandatory step for all changes to covered systems. It adds five minutes to each change process and maintains the accuracy of the E26 compliance documentation between class surveys.

✅ Key Takeaways — Lesson 41
  • The newbuild E26 compliance journey: specification (cybersecurity architecture and E27 requirements), shipyard build (E27 equipment integration and configuration), class society survey (CRA, network architecture, access control, and procedures verification).
  • The retrofit compliance journey begins with a gap assessment producing a prioritised remediation plan, sequenced by risk impact: network segmentation first, then access control, then logging, then documentation.
  • Class societies implement E26 for existing vessels at Special Survey or dedicated E26 survey — vessels unable to achieve full compliance may receive time-limited conditions of class rather than immediate deficiency, recognising that retrofit is a multi-year programme.
  • An operationally mature maritime cyber resilience programme has eight components: governance, asset management, risk management, technical controls, detection and monitoring, incident response, recovery, and training — all integrated into the ISM Code SMS.
  • The continuous improvement cycle maintains programme effectiveness between class surveys: threat intelligence integration, vendor patch management, incident learning, and programme metrics tracking KPIs across the fleet.
  • Change management integration is the critical operational gap: every change to covered vessel systems must include a cybersecurity impact assessment step that updates the CRA and network architecture documentation — without this, compliance erodes through normal operational change.
