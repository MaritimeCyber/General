SOAR: Security Orchestration, Automation and Response

Captain Paul
Maritime Cybersecurity · IACS UR E26/E27
September 2026
🎯 Lesson Objective

After this lesson you can define SOAR and explain its three pillars (Orchestration, Automation, Response), describe the anatomy of a SOAR playbook and how it responds to a security alert, list common automation use cases that save the most analyst time, compare Splunk SOAR and Microsoft Sentinel Playbooks as the two dominant platforms, and explain how SOAR enables small maritime security teams to operate at the scale of much larger SOCs.

A typical SOC alert requires, before an analyst can begin meaningful investigation, a series of repetitive enrichment steps: look up the source IP address in threat intelligence feeds, check whether the affected user account has had recent password resets, query the EDR for the process history on the affected endpoint, check whether the same IP has appeared in other recent alerts, and open a ticket in the case management system. These steps might take 10-15 minutes per alert. A busy SOC handling 200 alerts per day is spending 33-50 analyst-hours on mechanical enrichment alone.

SOAR — Security Orchestration, Automation, and Response — was built to eliminate this mechanical overhead. SOAR platforms connect to every security tool in the environment through integrations (APIs, webhooks, pre-built connectors), execute predefined response playbooks automatically when alerts fire, and deliver a pre-enriched incident to the analyst: 'Here is the alert, here is the threat intelligence on the IP, here is the process tree from the EDR, here is the user's recent authentication history, and here is the ticket already opened.' The analyst's first action is informed investigation, not mechanical data gathering.

For maritime security teams — typically small teams managing a complex environment of shore infrastructure and vessel systems — SOAR is particularly valuable. A team of three security engineers cannot manually triage 200 alerts per day and also perform threat hunting, detection engineering, and incident response. SOAR enables the same team to effectively operate at the scale of a team three times its size by automating the tier-1 work that does not require human judgement.

1. SOAR Pillars — Orchestration, Automation, Response

1. SOAR Pillars — Orchestration, Automation, Response
1
Orchestration

Orchestration is the coordination of multiple security tools into a unified workflow. Instead of an analyst manually querying three different platforms for information about an IP address, the SOAR orchestrates all three queries simultaneously and aggregates the results. Orchestration requires integrations: pre-built connectors or custom API calls for each tool in the environment. A mature SOAR deployment integrates: the SIEM (alert source), EDR platforms (endpoint context and response), threat intelligence platforms (indicator enrichment), firewalls (blocking actions), email gateways (email incident context), ticketing systems (case management), and communication platforms (Teams, Slack notifications).

2
Automation

Automation eliminates human involvement in repetitive, rule-based tasks that have deterministic outcomes. If an alert fires for a brute-force attack from an external IP, the automated response is always the same: block the IP at the firewall, query the threat intelligence database for context, check whether the targeted account was successfully compromised (successful logon after the failed attempts), and open a ticket. There is no judgement required; the same action should always be taken. Automating these deterministic tasks frees analysts for the judgement-intensive work that automation cannot replace.

3
Response

The response pillar covers the actions taken when a threat is confirmed: endpoint isolation, user account disabling, firewall rule creation, malicious email deletion from user inboxes, DNS sinkholing. SOAR executes these response actions via API calls to the relevant tools. Response actions can be fully automated (auto-isolate when ransomware is detected), semi-automated (auto-isolate proposed, analyst approves with one click), or analyst-initiated (analyst triggers isolation manually from the SOAR case interface). The tier of automation is set based on risk tolerance and confidence in the detection.

4
Case Management

SOAR platforms include integrated case management: every alert generates a case, automated enrichment is documented in the case timeline, analyst actions are recorded, and the case is closed with a disposition (true positive, false positive, or undetermined) and lessons-learned notes. Case data provides the raw material for SOC metrics (MTTD, MTTR, false positive rate) and the incident database that informs future detection rule development.

2. SOAR Playbooks — Anatomy and Examples

2. SOAR Playbooks — Anatomy and Examples
1
Playbook Structure

A SOAR playbook is a workflow: a trigger (an alert type or condition), a sequence of actions (API calls, conditional logic, human decision points), and outcomes (actions taken, case notes written, notifications sent). Playbooks are built visually (drag-and-drop workflow editors in Splunk SOAR and Microsoft Sentinel) or programmatically (Python scripts in Splunk SOAR). The trigger-action-outcome structure means playbooks are readable and auditable — security engineers can review the logic of every automated response.

2
Phishing Response Playbook

A phishing email response playbook: Trigger — email security alert for suspected phishing. Actions: (1) Extract all URLs and attachments from the email. (2) Query VirusTotal and threat intelligence feeds for each URL and file hash. (3) Check which users received the email and whether any clicked the link. (4) If any user clicked: query EDR for process execution on that user's endpoint in the 60 minutes after the click. (5) If malicious process detected: isolate endpoint, disable user account, notify security team. (6) Delete the phishing email from all recipient inboxes. Outcome: case documented, analyst notified with full context. Time from alert to completed response: 90 seconds.

3
Brute Force Response Playbook

Brute force response: Trigger — 10+ failed logons against a single account in 5 minutes. Actions: (1) Check whether any successful logon followed the failed attempts. (2) Query GeoIP for the source IP — is it in an expected location? (3) Query threat intel for the source IP — is it a known bad actor? (4) If successful logon and anomalous location: disable the account, terminate active sessions, notify the account owner. (5) Block the source IP at the firewall if it is threat-intel confirmed malicious. (6) Open a case with all context pre-populated. Analyst receives a pre-enriched, pre-actioned case — they review and confirm, they do not start from scratch.

4
Maritime-Specific Playbook — Vessel Alert

A vessel-specific playbook: Trigger — VSAT management interface logon from non-whitelisted IP. Actions: (1) Query shore office records for any expected maintenance activity from external vendors today. (2) Send automated notification to the vessel master and shore-based IT team. (3) Capture current VSAT configuration and log it as evidence. (4) If no maintenance activity scheduled: escalate to on-call security analyst with full context. (5) Open a case tagged as 'Vessel: [Vessel Name]' for fleet-level correlation. Time from logon anomaly to shore-side notification: under 60 seconds.

3. SOAR Platforms — Splunk SOAR and Microsoft Sentinel Playbooks

3. SOAR Platforms — Splunk SOAR and Microsoft Sentinel Playbooks
1
Splunk SOAR

Splunk SOAR (formerly Phantom) is the leading independent SOAR platform, with 350+ pre-built app integrations and a Python-based playbook engine. Playbooks are built visually or as Python code, enabling both simple drag-and-drop workflows and highly complex, programmatic automation logic. Splunk SOAR integrates natively with Splunk ES (notable events trigger SOAR playbooks automatically) but also supports non-Splunk SIEM sources. For large maritime security operations with complex, diverse tool environments, Splunk SOAR's integration breadth is a significant advantage.

2
Microsoft Sentinel Automation (Playbooks)

Microsoft Sentinel implements SOAR through Azure Logic Apps, branded as 'Automation' and 'Playbooks'. Logic Apps provide a low-code visual workflow editor with 400+ connectors to Microsoft and third-party services. Sentinel analytics rules trigger playbooks automatically; playbooks can also be run manually on incidents by analysts. The tight integration with Microsoft services (Teams, Outlook, Defender for Endpoint, Azure AD) makes Sentinel Playbooks particularly powerful for Microsoft-centric environments. The no-code/low-code nature is accessible to security engineers without Python experience.

3
Choosing a SOAR Platform

Organisations already using Splunk ES will typically deploy Splunk SOAR for seamless integration. Organisations on Microsoft Sentinel should use Sentinel Automation (Logic Apps) for native integration and zero additional licensing cost. Both platforms support the use cases most relevant to maritime security operations — the key driver is ecosystem alignment, not platform capability. Start with the SOAR that integrates natively with your existing SIEM; complexity of customisation is a secondary concern.

✍️ Author Insight — From the Field
Captain Paul · Maritime Cybersecurity Consultant · IACS UR E26/E27

During E26 CRSI assessments, SOAR is often positioned as an advanced capability for organisations that have already solved the basics — detection rules, alert management, and incident response procedures. The typical recommendation is sequential: establish detection coverage first, then automate the response. This is correct in principle, but the automation opportunity should not be deferred indefinitely. Even a simple SOAR playbook that auto-enriches every alert with threat intelligence context and opens a pre-formatted ticket reduces per-alert handling time by 5-10 minutes. Across a security operation handling 50 vessel alerts per day, that is 4-8 hours of analyst time saved daily — time that can be redirected to threat hunting, detection engineering, and actual investigation. The ROI calculation for SOAR is almost always compelling; the barrier is usually integration development time, not technology cost.

Practical first step: Identify your three highest-volume, most repetitive alert types. Document the manual steps an analyst currently takes to triage each alert. For each manual step, identify which SOAR integration would automate it (VirusTotal API for IP/URL lookups, EDR API for endpoint context, ITSM API for ticket creation). Build the first playbook for the highest-volume alert type. Measure time saved per alert. Use that measurement to justify the next playbook development investment.

✅ Key Takeaways — Lesson 25
  • SOAR orchestrates multiple security tools, automates deterministic tasks, executes response actions, and manages case documentation — transforming alert-driven manual workflows into automated, auditable processes.
  • SOAR playbooks encode response logic as visual or code-based workflows: trigger (alert type) → actions (API calls, conditional logic, human approval points) → outcomes (response executed, case documented).
  • Common high-value SOAR playbooks: phishing response (email deletion, user notification, endpoint investigation), brute force response (account protection, IP blocking), and vessel-specific playbooks (VSAT anomaly notification, vessel alert case creation).
  • Splunk SOAR offers broad third-party integration depth suitable for complex diverse environments; Microsoft Sentinel Automation (Logic Apps) provides native Microsoft ecosystem integration with low-code accessibility.
  • For small maritime security teams, SOAR's primary value is time multiplication: automating 10-15 minutes of per-alert enrichment across 50 daily vessel alerts recovers 8-12 analyst-hours per day for higher-value work.
  • SOAR implementation follows detection maturity: establish detection coverage and alert procedures first, then automate the highest-volume, most repetitive response workflows.
