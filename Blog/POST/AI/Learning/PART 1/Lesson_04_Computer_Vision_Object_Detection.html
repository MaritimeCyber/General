Computer Vision and Object Detection

ImageNet · CNN Architecture · Object Detection · YOLO · Semantic Segmentation · Foundation Vision Models (SAM, CLIP) — how machines learned to see, and how that capability is transforming maritime port operations, shipyard inspection, and vessel safety.

🎯 Lesson Objective

After this lesson you can explain the image classification task and how CNNs approach it; describe the ImageNet benchmark and why it was a turning point; explain what object detection adds to image classification and how YOLO achieves real-time detection; distinguish between classification, detection, and segmentation tasks; and identify concrete maritime applications of each computer vision capability.

Computer vision is the field of AI concerned with enabling machines to derive meaningful information from visual inputs — images, video, and depth sensor data. It is not a new aspiration: the first image segmentation programs were written in the 1960s. What changed in 2012 was the combination of large labelled datasets, deep convolutional networks, and GPU computation — and the result was a step change in capability that turned computer vision from an academic specialty into a core enabling technology for robotics, autonomous vehicles, medical diagnosis, and maritime operations.

This lesson builds on the CNN foundations from Lesson 3 and shows how they were applied to progressively harder vision tasks: first classification (what is in this image?), then detection (where in this image is the object?), then segmentation (which pixels belong to which object?), and finally the foundation models that unify vision and language.

For maritime professionals, the practical stakes are high: computer vision is the technology enabling autonomous port cranes, hull inspection drones, shipyard weld quality AI, and CCTV-based anomaly detection on vessels and port facilities.

1. The Image Classification Problem

Image classification is the task of assigning a label to an entire image from a fixed set of categories. Given an image of a container ship, output "container ship." Given an image of a propeller defect, output "cavitation erosion" or "impact damage." The classification model outputs a probability distribution over all possible categories; the highest-probability category is the prediction.

Before deep learning, this was done with hand-crafted features: SIFT (Scale-Invariant Feature Transform), HOG (Histogram of Oriented Gradients), or colour histograms, fed into a Support Vector Machine classifier. Achieving 75% accuracy on a 1000-class problem required years of hand-engineering and was considered excellent.

After AlexNet (2012), the field moved to learning features directly from raw pixel data using CNNs, and accuracy on the same 1000-class problem exceeded human performance by 2015. The key enabler was the ImageNet dataset.

2. The ImageNet Moment — How Data Scale Changed Everything

ImageNet (Deng et al., CVPR 2009) is a dataset of over 14 million images manually labelled with one of 1,000 categories, assembled by Fei-Fei Li at Stanford using Amazon Mechanical Turk for annotation. The ImageNet Large Scale Visual Recognition Challenge (ILSVRC) ran annually from 2010 to 2017 and became the benchmark that drove a decade of computer vision progress.

ILSVRC Top-5 Error Rate — The Story in Numbers
2010 28.2% — Pre-deep-learning state of the art (NEC / Illinois).
2012 15.3% — AlexNet (Krizhevsky, Sutskever, Hinton). 10.8pp improvement in a single year. Marks the start of the deep learning era in vision.
2014 6.7% — VGGNet (Simonyan, Zisserman). 19 uniform 3×3 convolutional layers.
2015 3.57% — ResNet-152 (He et al., Microsoft). Below estimated human performance (~5.1%). Residual connections solve the training instability of very deep networks.
2017 2.25% — SENet (winner of final ILSVRC). Challenge retired. The classification problem is considered solved at this benchmark level.

The ImageNet insight for maritime AI: scale of labelled data is the primary driver of vision model quality. The challenge for maritime applications is that maritime-specific datasets — images of vessel hulls, cargo seals, weld defects — are orders of magnitude smaller than ImageNet. Transfer learning (taking a model pre-trained on ImageNet and fine-tuning on maritime data) is the standard approach to bridge this gap.

3. Object Detection — Finding Objects in Images

Object detection extends classification: instead of labelling the whole image, it simultaneously identifies which objects are present and where they are located, expressed as bounding boxes (x, y, width, height) around each detected object. A single image may contain multiple objects of different classes, each with its own bounding box and class probability.

The first competitive deep learning detection systems used a two-stage approach: a Region Proposal Network (RPN) first proposes candidate regions likely to contain objects, then a CNN classifies each proposed region. R-CNN (Girshick et al., 2014), Fast R-CNN, and Faster R-CNN (Ren et al., NIPS 2015) iteratively refined this pipeline, achieving high accuracy but at 5–7 fps — too slow for real-time applications.

Key Detection Metrics

IoU (Intersection over Union): Measures how much the predicted bounding box overlaps with the ground-truth box. IoU > 0.5 is typically considered a correct detection; IoU > 0.75 is a high-quality detection.

mAP (mean Average Precision): Averages the precision-recall curve across all classes and IoU thresholds. The standard benchmark metric for detection models — allows fair comparison across different systems and datasets.

4. YOLO — Real-Time Object Detection

YOLO (You Only Look Once) (Redmon et al., CVPR 2016, arXiv:1506.02640) reimagined object detection as a single-pass regression problem: instead of first proposing regions and then classifying them, YOLO divides the image into an S×S grid and predicts bounding boxes and class probabilities simultaneously for all cells in a single forward pass through the CNN.

The result was 45 fps on a Titan X GPU (vs. 7 fps for Faster R-CNN) with competitive accuracy — fast enough for real-time video analysis. YOLO has been successively improved through versions 2 through 11, with each version improving speed/accuracy trade-offs. YOLOv8 (Ultralytics, 2023) is the most widely deployed version in production industrial vision systems as of 2025, including maritime applications.

YOLO in Maritime — Deployed Applications
  • Container seal integrity inspection: Camera on crane or gantry detects seal number, seal type, and visual damage/anomalies as containers are loaded. Eliminates manual inspection steps.
  • Port gate CCTV — vehicle and personnel detection: Detects unauthorised access to secured areas (vessel gangway, crane operating zone) in real time from existing CCTV infrastructure.
  • Shipyard weld inspection: Camera mounted on inspection robot detects weld anomalies (porosity, cracks, undercut) from images taken during production. Faster and more consistent than manual X-ray-only inspection.
  • Vessel hull inspection (underwater drone): ROV camera footage processed by YOLO-based detector identifies biofouling patches, anode consumption, and hull coating damage, georeferenced to a 3D hull model.
  • Vessel traffic monitoring (VTS): AIS data fusion with CCTV detection of vessels entering harbour channels — detects non-AIS targets (small craft, spoofed vessels) that appear on camera but not on radar/AIS.

5. Beyond Detection — Segmentation, Depth, and 3D Vision

Semantic segmentation assigns a class label to every pixel in an image, not just a bounding box around an object. A semantic segmentation model processing a port aerial image might colour every pixel as "vessel," "quay," "crane," "water," or "container stack." This is far more computationally demanding than detection but provides richer spatial information.

Instance segmentation (Mask R-CNN, He et al., ICCV 2017) extends this by providing separate masks for each individual object instance — distinguishing between 12 different containers stacked together, not just "there are containers here."

🔍 Semantic Segmentation

Every pixel gets one class label. Objects of the same class are not distinguished. Used for: navigable waterway detection in autonomous vessel path planning; ice classification in Arctic route optimisation; hull coating condition mapping from underwater drone footage.

🎯 Instance Segmentation

Each object instance gets its own pixel mask. Enables counting and individual tracking. Used for: individual container identification and tracking through port terminals; individual crew member detection for access control; weld bead segmentation for dimensional inspection.

6. Foundation Vision Models — SAM and CLIP

The latest generation of vision AI moved beyond task-specific models (one model per task) toward foundation models — large models trained at scale that generalise across many vision tasks without task-specific fine-tuning. Two are particularly significant for maritime applications:

Foundation Vision Models

CLIP (Contrastive Language-Image Pretraining) (Radford et al., OpenAI, 2021, arXiv:2103.00020): Trained on 400 million (image, text) pairs scraped from the internet, CLIP learns a shared embedding space for images and text. Given an image and a text description, CLIP scores how well they match. Zero-shot classification: given an image of a vessel, CLIP can classify it as "bulk carrier," "container ship," or "tanker" without having been explicitly trained on those labels — purely by matching image embeddings to text embeddings.

SAM (Segment Anything Model) (Kirillov et al., Meta AI, 2023, arXiv:2304.02643): Trained on 1.1 billion masks, SAM can segment any object in any image given a point, bounding box, or text prompt — without task-specific training. Applications in maritime: segment any hull region of interest from an inspection image without re-training per vessel class or defect type; segment weld regions from arbitrary camera angles for dimensional inspection.

The foundation model paradigm shifts the economics of maritime vision AI: instead of collecting thousands of labelled maritime images to train a task-specific model, an operator can prompt SAM or CLIP with natural language descriptions and apply the model to new vessel types or inspection tasks immediately. This significantly lowers the barrier to deploying vision AI in maritime contexts — but also shifts the security burden to the model provider and the prompt design.

7. Maritime Connection — Vision AI and Cyber Risk

Every vision AI system deployed in maritime operations — from port CCTV analytics to underwater inspection drones — has a cyber attack surface that is distinct from traditional IT/OT systems. Understanding this surface requires understanding how these models work.

Vision AI Cyber Risk — Key Attack Classes
  • Adversarial patches: Physical stickers or markings on containers, vessels, or port assets that cause systematic misclassification by the detection model. Demonstrated in published research with real-world applicability to port access control and container inspection.
  • Training data poisoning: An attacker who can introduce crafted images into the training dataset can embed backdoors — patterns that cause specific misclassifications on demand (e.g., a specific seal type is always classified as "intact" even when damaged).
  • Camera feed manipulation: Spoofing or replaying CCTV feeds to an AI-based access control system — a physical security bypass that exploits the AI's reliance on the camera as a trusted sensor.
  • Model extraction: Querying a vision AI API with carefully chosen inputs to reconstruct the model's decision boundary, enabling subsequent adversarial attacks without white-box access to the model weights.
  • IACS UR E26 relevance: Section 4.2.3 addresses prevention of malware and section 4.2.4 addresses access control. AI-based systems that enforce either capability must have their adversarial robustness evaluated as part of the cyber resilience assessment.
✍️ Author Insight
Captain Paul — Maritime Cybersecurity Consultant

During E26 CRSI 프로젝트 수행, I have seen increasing adoption of AI-based CCTV analytics in port and vessel access control contexts. The typical deployment pattern is: existing CCTV cameras → video stream to a shore-based server → YOLO-based detection → alert to security personnel if anomaly detected.

The cyber risk question that is almost universally absent from the procurement process: "What happens if someone learns which detection model we are using and tests adversarial inputs against our camera feeds?" This is not a theoretical concern. YOLO model weights and architectures are public; an attacker who knows which version of YOLO a port uses can generate adversarial inputs in the same afternoon.

The mitigation is not to avoid AI-based vision systems — their operational value is real. The mitigation is to treat the model version, training data distribution, and detection thresholds as sensitive configuration data (protected under IACS UR E26 Section 4.1), and to include adversarial robustness in the periodic security assessment scope alongside traditional penetration testing.

🔑 Key Takeaways
  • ImageNet (1.2M labelled images, 1,000 classes) was the dataset that enabled the deep learning revolution in computer vision. Transfer learning from ImageNet-pretrained models is the standard approach for maritime-specific tasks.
  • Image classification labels a whole image; object detection adds bounding boxes; segmentation assigns class labels to every pixel. Each task enables different maritime applications.
  • YOLO achieves real-time detection (45+ fps) by treating detection as a single-pass regression over a grid, rather than a two-stage region proposal + classification pipeline.
  • YOLOv8 is the most widely deployed production detection model in maritime applications as of 2025, including container inspection, port surveillance, and hull inspection drones.
  • CLIP enables zero-shot vision classification by aligning image and text embeddings. SAM enables prompt-driven segmentation of any object without task-specific retraining.
  • Vision AI systems in maritime are vulnerable to adversarial patches, training data poisoning, and camera feed manipulation. Model version and configuration are sensitive cybersecurity data.
