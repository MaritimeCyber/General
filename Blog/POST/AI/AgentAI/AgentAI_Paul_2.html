Part 1 — The Brain
LLM: What Agent AI's Brain Actually Does

1. What Is an LLM?

An LLM (Large Language Model) is an AI model trained on hundreds of billions of pieces of text data. By learning from the vast body of text humanity has produced — internet documents, books, papers, code, legal documents — it internalizes the patterns and knowledge embedded in language.

Beyond simply generating text, modern LLMs can understand context, reason, and decide what to do next. This ability is what makes it possible for an LLM to serve as Agent AI's "brain."

💡 What the LLM Does Inside an Agent
→

Understand the Goal: Interprets the user's instruction and grasps intent

→

Build a Plan: Breaks the goal down into steps to achieve it

→

Choose Tools: Decides which tools (search, calculation, database lookup, etc.) each step needs

→

Interpret Results: Interprets each tool's output and decides the next action

→

Deliver a Final Answer: Synthesizes the whole process into a result for the user

Part 2 — 4 Core Capabilities
Planning · Memory · Tool Use · Multi-step Reasoning

2. Planning — Breaking a Goal Into Steps

Agent AI's first core capability is decomposing a complex goal into small, actionable steps. This is called Task Decomposition.

Planning Example: Preparing for a Vessel Cybersecurity Audit
Goal: "Prepare a readiness report for the DNV cybersecurity audit"
1

Search the latest DNV cybersecurity regulations and extract requirements

2

Query the vessel CBS database → assess current system status

3

Perform a gap analysis: regulatory requirements vs. current status

4

Prioritize risks and build an action plan

5

Draft the audit readiness report → share it with the responsible person

The human gave a single goal. The agent planned and executed all five remaining steps on its own.

⚠️ Without a Plan, It Fails

Unlike an instant answer to a simple question, a complex goal can't be executed in one shot without a plan. An agent with weak planning ability loses its way midstream or drifts off course. A good agent thinks carefully at the start and can revise its plan along the way.

3. Memory — The Ability Not to Forget

In Part 1, we mentioned "no memory" as one of the biggest limits of traditional LLMs. Agent AI addresses this problem with several different kinds of memory.

The 4 Types of Memory in Agent AI
💭 Working Memory Current Conversation

Maintains context for the task currently in progress. Similar to human short-term memory. Disappears when the conversation ends.

💾 External Memory Database

Stores information in a vector database or a regular DB and retrieves it when needed. Remembers meeting notes, past analysis results, vessel data, and more for the long term.

🧠 Semantic Memory Knowledge Baked Into the Model

General knowledge the LLM internalized through training. IACS regulation content, maritime terminology, and technical concepts fall into this category.

📋 Episodic Memory Past Experience

Stores results and lessons from previously performed tasks. Information like "Vessel A had this problem during last inspection" can be used in the next inspection.

💡 Application to the Maritime Industry

If you store CBS data for 50 vessels in External Memory, the agent can instantly retrieve "Vessel A's ECDIS patch history." Using five years of audit results as Episodic Memory, the agent discovers recurring problem patterns on its own.

4. Tool Use — Hands and Feet Appear

What fundamentally separates Agent AI from a simple chatbot is that it can use external tools. If the LLM is the brain, tools are the hands and feet. An agent selects and executes the tools it needs to reach its goal, on its own.

Types of Tools Agent AI Can Use
🔍 Search Tools

Web search, document search, regulation DB lookup, patent search

📊 Data Tools

Excel/CSV analysis, database queries, statistical calculation

📧 Communication Tools

Sending email, Slack messages, generating reports

🔧 System Tools

API calls, code execution, ERP system integration

📄 File Tools

Reading PDFs, drafting Word documents, editing spreadsheets

🚢 Maritime-Specific Tools

AIS lookup, vessel monitoring systems, class society portal integration

💡 The Core of Tool Use: Deciding for Itself Which Tool to Use, and When

What matters isn't the tool itself, but the judgment to choose the right tool for the situation. "I need to find the latest IACS regulation" → use the web search tool. "I need vessel data" → use the DB lookup tool. The LLM makes this judgment call. Part 3 explains the MCP technology that makes this possible.

5. Multi-step Reasoning — Thinking That Chains Multiple Steps Together

Multi-step Reasoning is Agent AI's most powerful capability. It's not simply A → B, but chained, adaptive thinking — seeing A's result, deciding B, and then adjusting C based on B's result.

A Live Thought Process Example (Vessel Anomaly Detection Scenario)
[Thought] Detected abnormal traffic on the ECDIS. First, I need to analyze the traffic pattern.
[Action] Run the network log analysis tool
[Observation] Found repeated access attempts to port 22 from an external IP
[Thought] This is an SSH brute-force pattern. I need to check that IP against a threat intelligence database.
[Action] Run the threat IP lookup tool
[Observation] That IP is registered to a known malicious botnet
[Thought] Immediate blocking is needed, and it needs to be reported to class. I'll do both at once.
[Action] Apply a firewall block rule + draft an incident report

This process is called the ReAct (Reasoning + Acting) pattern. By alternating between thinking (Reasoning) and acting (Acting), it repeatedly gets closer to the goal. It closely resembles how a human expert works.

7. Agent AI's Current Limits — An Honest Discussion

Agent AI is powerful, but it isn't perfect yet. To use it in the field, you need to know these limits.

⚠️ Hallucination: it sometimes invents information that doesn't exist

It can present unverified information as fact. Errors can especially occur in regulation article numbers or figures, so critical items should always be checked against the source.

⚠️ Cost: token costs rise with task complexity

Running an agent consumes far more API calls and tokens than a simple Q&A. Cost planning that scales with the size of the task is essential.

⚠️ Infinite loops: it can get stuck repeating the same action without reaching the goal

In complex situations, an agent can fail to find the right path and fall into repetitive behavior. Designing when and how a human should monitor and step in is important.
